# Workflows spec: dispatch, Away mode, notifications, peer review, grind, jev, vault, built-in skills

Behavioural spec for rewriting the Python engine (`run-engine/`) in Go (`setu`). Source of truth is the Python at branch `setu`; every constant below is copied from it. Conventions used throughout:

- `DATA` = the data dir (Python: `$CLAUDE_PLUGIN_DATA` or `~/.claude/plugins/data/ai-workflow`; the Go app picks its own root, but keep the relative layout below).
- "Atomic write" = tmp file in the same dir + fsync + rename. "json_lock(path)" = exclusive `flock` on `<path>.lock`, not re-entrant. "backup_if_corrupt(path)" = a present-but-unparsable or non-object JSON file is renamed to `<path>.corrupt-<unix ts>` (warn once), then the write proceeds.
- Times are epoch seconds (float) in records unless a field is explicitly ISO-8601 (`YYYY-MM-DDTHH:MM:SSZ`, UTC).
- All GitHub access is the `gh` CLI (no HTTP client). Timeouts: `gh` 60 s in dispatch resolve, 120 s in the tick and merge, 30 s for `gh issue view`.
- Dropped for the Go rewrite, mentioned once here and not specced: **herdr** (`Herdr`/`HerdrApp` lane runners, `--runner herdr|herdr-app`, `hc`/`herdr-app` CLIs, `--workspace`, `herdr-dispatch` skill) and **codex** (`harness_codex`, Codex accounts, `--kind codex`, `herdr_codex_words`, `codex_args`, the inlined-skill Codex prompt). Only the `headless` runner survives; `runner` is therefore implicit.
- Dependencies that live in other specs but that this area calls (contracts only): session store (`ui_sessions`: `list_sessions`, `load`, `update`, `update_pending`, `claim_answer`, `restore_round`, `answer_text`, `is_answerer`), session runner (`ui_runner`: `start`, `send_prompt`, `resume`, `resume_stopped`, `stop`, `agent_refusal`, `limits`), board poller snapshots (`ui_poller`), settings (`ui_settings`), `merge_gate`, `aiw ci`, `aiw threads`, `aiw ask`.

Table of contents: 1 checkouts registry; 2 dispatch; 3 AFK / Away mode; 4 notifications; 5 peer review; 6 grind (UI side); 7 jev; 8 vault; 9 tailscale; 10 usage polling; 11 migrate; 12 built-in skills and the `setu` verbs they need; 13 pr-grind merge proposal.

## 1. Checkouts registry (`dispatch.py`)

File `DATA/checkouts.json`: `{ "<owner>/<repo>": "<absolute checkout path>" }`. Slugs for repos not yet on GitHub are `local/<name>`.

- `read_checkouts()`: `{}` for missing / zero-byte / non-JSON / non-object. Never raises. Lookups elsewhere are **case-insensitive on the slug**.
- Writes (`register`, `rename`, `remove`) take `json_lock(checkouts.json)` then `backup_if_corrupt`, then read-modify-write, atomic write, compact `json.dumps`.
- `register_checkout(slug, path)`: set key. Writes only the pair; never environment or `.env` content.
- `rename_checkout(old, new)`: re-key keeping the path. Returns false if `old` is absent or any existing key equals `new` case-insensitively (nothing overwritten).
- `remove_checkout(slug)`: unregister only (clone on disk untouched). False if absent.
- Path key `checkouts` in `aiw paths` points at this file.

## 2. Dispatch (`dispatch_run.py`, `dispatch_cli.py`, `ui_dispatch.py`, `dispatch_runners.Headless`)

An **epic's open child issues** (or 1..30 hand-picked issues of one repo) run as **lanes** in dependency order up to a cap, each lane a headless agent session driving `implement-issue` -> `pr-grind` -> merge -> after-merge. The UI server ticks every live dispatch; the CLI and HTTP API only edit the record.

### 2.1 Data

`DATA/dispatches/<id>.json`, `<id>` = 12 lowercase hex (`uuid4().hex[:12]`; any other id is `ValueError("bad dispatch id")`). Per-dispatch lock `DATA/dispatches/<id>.lock` (flock, not re-entrant); store-wide lock `DATA/dispatches/.store.lock` (guards the "is this issue already a lane" check + save of a new dispatch). Archive dir `DATA/dispatches/archive/`. Saves are atomic, `indent=1`.

```
Dispatch {
  id, epic: "owner/repo#N" | null, title, runner: "headless",
  workspace: null,                     # herdr-only, drop
  settings: Settings, state: "running"|"paused"|"done"|"cancelled",
  lanes: { "<owner/repo>#<n>": Lane }, events: [Event] (max 500, oldest dropped),
  created_at, ended_at|null,
  issues?: ["owner/repo#n", ...]      # present only for an issue-list dispatch (epic null; sorted by number)
  synced_at?, seen_done?: bool,       # tick bookkeeping / Inbox "seen"
  end_requests?: ["open-pr"|"qa"|"grind-pr"], final_prs?: {repo: url}, final_grinds?: {repo: handle}, qa?: handle
}
Settings (defaults) { max:2 (int 1..10), grind:"full" (off|simple|full), ci:"wait" (wait|defer|ignore),
  auto_merge:false, skip_approval:false, feature_branch:null, base_branch:null (fixed at start),
  model:null, effort:null (low|medium|high|xhigh|max), account:null (saved account label, 1..40 chars),
  max_cost:null (USD, 0 < x <= 10000) }
Lane { repo, n, title, deps:[key], base, stage, skip_reason, handle:{session:<id>}|null, handles:[...every handle ever],
  pr:int|null, started_at, ended_at,
  flags: paused, paused_by:"dispatch"|null, held:str|null, needs_you:str|null, gate:str|null,
         merge_error, merge_fails:int, merge_at, hold_merge, force_merge, limited_until, idle_since,
         nudged (grind due token), ci_fixed (sha), none_sha, none_since, channel, reviewer,
         outbox:[["send",text]|["close",null]], restart:bool, afk_retries, afk_retry_at, afk_retry_for }
Event { at, lane:key|null, kind, text }
```

`load()` overlays `DEFAULTS` under stored settings (records written before a key existed read its default). `list_all()` = every readable `*.json` (unreadable skipped), newest `created_at` first.

**Settings validation (`check_settings`)** - each failure is a `ValueError` (HTTP 400): grind in {off,simple,full}; ci in {wait,defer,ignore}; `max` an int (not bool) 1..10; `auto_merge`/`skip_approval` coerced to bool; unknown keys rejected; `model` matches `[A-Za-z0-9][\w.\[\]:/-]{0,79}`; `effort` in the list; `account` a string 1..40; `max_cost` positive number <= 10000 (bool rejected); `feature_branch`/`base_branch` match `[A-Za-z0-9._/-]{1,100}`; `base_branch != feature_branch`. In the UI path (`ui_dispatch._settings`), `account` must also be a label saved in Settings. An issue-list dispatch refuses any `feature_branch`. `set_settings` refuses `base_branch` ("fixed at start").

### 2.2 Lane stages

`queued -> implementing -> grinding -> merge_gate -> (awaiting_merge) -> followups -> closed`; `conflict_fix` is a detour from the gate; `skipped` is a dead end (needs refine, user skip, or start failed). `ACTIVE = implementing, grinding, merge_gate, conflict_fix, awaiting_merge, followups`.

New lane on `sync_lanes`: `stage = "queued"` if the issue has the `refined` label, else `"skipped"` with `skip_reason = "needs refine"`. Re-sync of an existing lane: deps become the **union** of known and newly listed (a re-read lists only still-open blockers); a `needs refine` skipped lane whose issue is now refined becomes `queued`. If the dispatch was `done` and a re-sync adds a lane or un-skips one, it flips to `paused` (`ended_at` null, event `paused`: "new issues joined: refine them, then resume").

### 2.3 Pure step function

`step(lane, facts, settings, now) -> (patch, actions)`. Actions: `("send", text)`, `("merge", pr_n, sha)`, `("close",)`, `("continue",)`, `("notify", kind, text)`.

Facts per lane (built by the server from the poller snapshot, grind state files and runner status):
```
{issue_open, refined, blockers_open:[key],
 pr: null | {n,url,draft,state OPEN|MERGED|CLOSED, ci success|failure|pending|none, conflict, approved, changes_requested, threads_open, sha},
 grind: null | {state idle|running|paused|done, reason, due: token|null},
 slack: bool (resolver gave a path and no skip), channel, solo: bool (repo owner == gh login), agent: working|idle|blocked|gone|unknown|null, limited_until}
```

Constants: `NONE_GRACE_SECONDS=300`, `MERGE_RETRY_SECONDS=300`, `IDLE_GRACE_SECONDS=180`, `LIMIT_BUFFER_SECONDS=60`, `MERGE_FAILS_BEFORE_NEEDS_YOU=3`, `MAX_EVENTS=500`, `CONTINUE = "Continue from where you were stopped."`.

Rules, evaluated in this order. A lane in a non-ACTIVE stage or `paused` yields nothing. `to(s, why)` = patch `stage=s, needs_you=None, held=None, idle_since=None, merge_error=None, merge_fails=0` and, if `why`, a notify action `(s, why)`.

1. **Usage limit.** `facts.limited_until > now`: patch only `limited_until` (if changed), no actions. Else if the lane has a stored `limited_until`: clear it; if `now >= stored + 60` emit `continue`; return.
2. **Merged anywhere** (`pr.state == MERGED`, any stage but `followups`): `to("followups")`, `pr = pr.n`, send `followups_prompt`.
3. **Session gone** (`agent == "gone"`) in `implementing|grinding|conflict_fix|followups` (except `followups` with the issue already closed): set `needs_you = "the lane session is gone"` once, notify `needs_you` "the lane session is gone: retry it"; return.
4. **implementing:** `ready = pr OPEN and not draft`. Track the PR number as soon as it exists (`patch.pr`). If `ci != "wait"` is false (i.e. mode `wait`) and ready and `pr.ci == failure` and agent in (idle, null): set `held = "CI is red"` once (notify `held`, "CI is red on PR #n"), return. Otherwise clear `held`. If ready and (mode is defer/ignore or `pr.ci == success`): if grind on (`settings.grind != off and facts.slack`) `to("grinding")` + send `grind_prompt(pr.url, channel, ci)`; else `to("merge_gate")`. Else, with the `idle_guard` setting on, `_stalls()`; off, `_waits(..., "stopped without a ready PR")`.
5. **grinding:** grind switched off mid-run -> `merge_gate`. `grind.state == done`: reason contains `"approved"` -> `merge_gate`; else `held = "grind ended: <reason|?>"` (notify once per distinct text). `paused`: `held = "grind paused: <reason|?>"` (once). Else (idle/running): clear `held`; if `grind.due` set and != `lane.nudged` and agent in (idle,null): set `nudged = due` and send `grind_prompt`; elif agent `blocked` and no `needs_you`: `needs_you = "the grind waits on you"` + notify; elif agent != blocked and `needs_you` set: clear it.
6. **merge_gate / awaiting_merge:**
   - `pr.conflict` -> `to("conflict_fix")` + send `conflict_prompt(pr.n, base)`.
   - `pr.ci == failure` and mode `wait` -> drop a stale merge error, `held = "CI is red"` once (notify); return.
   - Clear `held` when there is no merge_error. Mode `defer` and red and `lane.ci_fixed != pr.sha`: `ci_fixed = sha`, send `ci_fix_prompt`.
   - `none_since/none_sha` bookkeeping: cleared when `pr.ci != none`; set to `now/sha` when ci is `none` and sha changed or unset.
   - Gate (skipped entirely when `lane.force_merge`) `_gate()`: ci `none` in wait/defer and `now - none_since < 300` -> "CI not registered yet" (after the grace a CI-less repo merges); else wait & ci != success -> "CI is not green"; defer & ci != success -> "waiting for green CI (defer)"; then `merge_gate.blockers(pr, solo or skip_approval)` (order: "PR is a draft", "PR has a merge conflict", "changes requested", "unresolved review threads", "no approving review" unless solo); then if grind on and not (`grind.state==done` and reason contains `approved`) -> "grind is not done". A gate reason: drop stale merge error, `awaiting_merge -> merge_gate`, `patch.gate = why`, return.
   - Gate clear: `gate = None`. If `force_merge` or (`auto_merge` and not `hold_merge`): no `pr.sha` -> `gate = "head commit unknown"` (never merge unpinned); elif `merge_at` null or `now - merge_at >= 300`: `merge_at = now`, emit `("merge", pr.n, pr.sha)`. Else (no auto-merge) if stage != awaiting_merge: `to("awaiting_merge", "PR #n is ready to merge")`.
7. **conflict_fix:** no conflict and (mode != wait or ci success) and agent in (idle,null) -> `merge_gate`. Still conflicting -> `_waits(..., "stopped with the conflict unresolved")`.
8. **followups:** issue closed and agent in (idle, gone, null) -> `to("closed")`, `ended_at=now`, emit `close`. Else `_waits(..., "followups stopped with the issue still open")`.

`_waits(agent, idle_why)`: `idle` starts `idle_since` (cleared when not idle); `needs_you = "waiting on you"` if `blocked`, `idle_why` if idle for >= 180 s, else null; a changed `needs_you` emits notify `needs_you` when set.

`_stalls(agent)` (implementing under the idle guard): `_waits` with no idle reason, so `blocked` still gives `needs_you = "waiting on you"`; idle for >= 180 s sets `stalled = "stopped before a PR"` (no `needs_you`, no notify yet), any other agent state clears it. `to()`, a gone session, "CI is red", `retry` and `skip` clear `stalled` too.

### 2.4 Prompts (the text the lane sessions receive)

With the built-in skills the `/blubird:...` commands become the app's own skill prompts (see section 12), but the *shape* is fixed:
- implement: `<implement-issue cmd> <n>` + ` (` notes joined by `; ` `)`: `PR #<pr> is already open for it: continue that PR on its branch, don't start over` ; `base branch <base>: branch from it, open the PR into it` ; (ci != wait) `CI mode <ci>: mark the PR ready after local checks and review pass; do not wait for CI`.
- grind: `<pr-grind cmd> <pr_url>` + ` --channel <id>` (channel alnum/underscore) else ` --reviewer <login>` (`[A-Za-z0-9-]{1,39}`, only when no channel) + for lanes `LANE_GRIND = " -- dispatch lane: re-arm the headless way (write next-poll, end the turn; no Monitor, no ScheduleWakeup)"` and, when ci != wait, `" Skip CI for now, complete the grind, then come back and fix the CI"` (`SKIP_CI_REPLY`).
- conflict: `PR #<n> conflicts with <base|its base>. Merge origin/<base|<base>> into the branch, resolve the conflicts, re-run the checks, push and wait for CI to be green. Don't mark anything else or merge.`
- ci fix: `CI is red on PR #<n>. Read the failing job's log, fix it locally, re-run the checks, push and wait for green.`
- followups: `<after-merge cmd> <n> (PR #<pr> for issue #<n> is merged: run the 'After the pull request is merged' section, not the implement steps)`.
- QA: `Final QA for epic <epic>[ on branch <fb>]: run <verifier-locally> against every child issue's acceptance criteria, then test the whole feature end to end in the running app with the browser tool. File each bug you find with <small-change> as a child issue of the epic.`
- `lane_base = feature_branch or base_branch or lane.base`.
- `stage_prompt(lane)` (used on restart): implementing->implement, grinding->grind (needs the PR url), conflict_fix->conflict, followups->followups, others none.

### 2.5 Scheduling and tick

`startable(d, facts)`: only when `d.state == running`; none if any lane has `limited_until > now`; free slots = `settings.max - count(ACTIVE)`; iterate lanes by `(n, key)`; take `queued`, unpaused lanes whose every dep is `closed` (a dep not in the dispatch counts as closed), that **have facts** (never launch on a guess: the repo's first fresh poll must exist) and whose `blockers_open` are all inside the dispatch.

`stranded(d)`: queued unpaused lanes that can never start: a dep with stage `skipped` -> `"blocked by skipped #<n>"`, or a cycle -> `"dependency cycle"` (recursive through queued deps; a dep outside the dispatch or active/paused is just waiting).

`diagnose(d, snapshots)` (pure; used by `doctor`): stranded reasons; `stale poll snapshot for <repo>: <error|not fetched yet>` for live repos whose snapshot is stale/errored; `needs you: <x>` / `held: <x>` for flagged lanes not already reported as stranded. Done/cancelled -> `[]`.

`tick(d, facts, runner, merge, now, notify, gh)` (caller holds the dispatch lock around load+tick):
1. For each lane: run its `outbox` (pop): `send` -> if it has a handle `runner.send`, else start a fresh session with that text (and save at once); `close` -> `runner.close`, handle=null. A failure sets `needs_you = "<kind> failed: <e>"` + event. If dispatch is `cancelled|done` stop here for the lane.
2. `restart` flag: close old session, start new with `stage_prompt` (if any), append handle, event `lane` "restarted in <stage>"; on error `needs_you = "restart failed: ..."`; `continue` to next lane (no step this tick).
3. Skip lanes with no facts this tick ("never move on a guess"). Skip step if the outbox just sent a prompt (facts predate it).
4. `step`, apply patch, event `stage` "<old> -> <new>" on change, then run actions:
   - `send` as above; `continue` -> `runner.send(handle, CONTINUE)`; `close` -> close handle if any; `notify` -> event of that kind.
   - `merge` -> `gh pr merge <n> -R <repo> --merge --match-head-commit <sha>` (120 s). Always `force_merge=false` after. Ok: clear `merge_error/merge_fails/held` and a `merge failed*` needs_you, event `merged` "merged PR #n"; with `ci=ignore` and ci in (failure,pending) add event `warning` "merged with red CI" / "merged with CI pending". Error text contains `conflict` (ci-insensitive) -> `stage=conflict_fix`, `merge_at=null`, send conflict prompt, event "merge_gate -> conflict_fix (GitHub refused the merge: conflicts)". Contains `not up to date` -> `gh pr update-branch <n> -R <repo>`; ok -> event `lane` "PR #n was behind its base: merged the base into it"; fail -> conflict_fix with event "(could not update the branch from its base)". Else: `merge_fails++`, `held = "merge failed: <err>"`, event `held` only if the error text differs from `merge_error`; at `>= 3` fails and no needs_you set `needs_you = "merge failed N times: <err>"` + event.
   - Any exception sets `needs_you = "<action> failed: <e>"`; one lane never stops the others.
5. `end_requests` (popped): `run_end` per action; success -> event `end`, failure -> event `needs_you` "<action> failed: <e>".
6. Launch `startable` lanes: `runner.start(lane, implement_prompt)`, `handle` and `handles` appended, `stage=implementing`, `started_at=now`, event "queued -> implementing", save. Failure -> `stage=skipped`, `skip_reason="start failed: <e>"`, event `needs_you`.
7. Running dispatch: strand notices - if no lane is ACTIVE ("idle") set `needs_you` to the strand reason once and event; a queued lane whose `needs_you` starts with a strand prefix but is no longer stranded is cleared.
8. Running dispatch whose lanes are all `closed|skipped` (and non-empty): `state=done`, `ended_at=now`, event `finished` "every lane is closed or skipped".
9. Save. Events of kind `needs_you, held, awaiting_merge, finished, warning` are also passed to `notify` (-> section 4 event `dispatch`).

**End actions** (`request_end`, never automatic; refused for an issue-list dispatch): `open-pr` needs `feature_branch`; `grind-pr` needs `final_prs`. Queued in `end_requests`, run by the next tick:
- `open-pr`: per repo (sorted lanes' repos; a repo already in `final_prs` is reused so a retry after a partial failure creates only the missing PR): base = `base_branch` or the repo default branch (`gh repo view <repo> --json defaultBranchRef -q .defaultBranchRef.name`, fallback `master`); `gh pr create -R <repo> --base <base> --head <feature_branch> --title "Epic #<n>: merge <fb>" --body "Every child of <epic> is merged into `<fb>`."`; last stdout line = URL -> `final_prs[repo]`.
- `qa`: start a session on the epic's repo with the QA prompt, handle in `d.qa`, label `qa-<epic n>`.
- `grind-pr`: per final PR start a session with `grind_prompt(url, lane=false)` (label `grind-<repo>`), handles in `final_grinds`.

**User actions** (`apply_lane_action`; all emit event `lane` <action>; effects on sessions go through the lane's `outbox`): `pause` (paused=true); `resume` (paused=false; if `paused_by` was set, `restart=true`); `skip` (close session if active, `stage=skipped`, `skip_reason="skipped by you"`); `retry` (clear held/needs_you/stalled/paused/merge_error; if stage skipped or implementing-without-PR: close session, `stage=queued`, handle=null; elif the hold was "CI is red" and a handle exists: outbox `send ci_fix_prompt`; elif ACTIVE: `restart=true`); `merge` (force_merge); `hold`/`unhold` (hold_merge); `send` (text 1..2000 chars non-blank, needs a handle; outbox send). Unknown action `ValueError`. Actions: `pause resume retry skip merge hold unhold send`.
`retry_failed`: every lane that is `skipped` with reason starting `start failed`, or has `needs_you`, or `held` -> `retry`; returns keys (user-skipped, needs-refine, closed, healthy untouched).
`set_state(running|paused|cancelled, now)`: cancelled sets `ended_at` and queues `close` on every active lane with a handle (paused ones too); paused with `now=true` pauses every active unpaused lane with `paused_by="dispatch"`, clears `needs_you/limited_until`, queues close ("dispatch paused now: N issue(s) stopped"); running restarts lanes with `paused_by == dispatch` (`paused=false, restart=true`, "dispatch running: N issues restarted"); event text `dispatch <state>`.
`archive_old(days=30)`: for done/cancelled dispatches with `(ended_at or created_at) < now - days*86400`, under the dispatch lock, move to `archive/`; running/paused/unreadable stay. Run once a day by the tick loop.
Ownership: `create()` raises `Conflict` (HTTP 409, carries the owning id) if any lane key already belongs to a non-done, non-cancelled dispatch (`owner_of`), checked under the store lock. `active_lane(repo, n|pr)` -> `(dispatch id, lane)` for a running/paused dispatch's ACTIVE lane for that issue or PR (case-insensitive repo) - used by autostart and the pr-grind re-entry to leave the PR to the dispatch.

### 2.6 Resolving the epic / issues (`dispatch_cli`)

- `parse_epic("owner/repo#N" | "N")`; bare `N` uses `gh repo view --json nameWithOwner -q .nameWithOwner` in the cwd (error "not in a GitHub checkout: give the epic as owner/repo#N").
- `resolve(epic)`: GraphQL (`gh api graphql -f query=... -f owner -f name -F n [-F after]`) of `issue(number).subIssues(first:100, after)` with `number title state repository{nameWithOwner} labels(first:100){nodes{name}} blockedBy(first:100){nodes{number state repository{nameWithOwner}}}`; up to 20 pages (`MAX_CHILD_PAGES`) else "epic has too many sub-issues". Only `OPEN` children. `bodies=true` adds `body` (kept apart, never stored in lanes/records).
- Child: `{repo,n,title,refined (label "refined"), deps}`; a blocker that is in the set -> dep key; an `OPEN` blocker outside the set -> reported in `outside` (warning "blocked by open X outside the epic|pick"). Children sorted `(n, repo)`.
- `resolve_issues(refs)`: 1..30 `owner/repo#N` all in one repo (aliased `i0..` GraphQL query); closed ones go to `closed` ("closed, left out"); not found -> "issue repo#n not found". Title `Small changes: #a, #b, #c +k more`.
- `preview()` (`aiw dispatch plan`, `POST /api/dispatches/plan`): `plan()` waves (Kahn layers of refined lanes, sorted by `(n,key)`; an unplaceable remainder warns "dependency cycle or blocked by an unrefined issue: ..."; unrefined -> "<k>: needs refine") plus warnings: outside blockers, closed, per repo with no registered checkout (non-headless only - drop), grind-resolver skip (`g.skip` or no path) unless grind off, missing base branch (`gh api repos/<repo>/git/ref/heads/<base> -q .object.sha`, fail-safe None), and **jev readiness**.
- Readiness: only when `jev.status()=="ok"`; score each refined lane body (<=30, 5 workers, 8 s total wait; not awaited past it) via `jev.ask("readiness","score", READINESS_QUESTION, body, levels=READINESS_LEVELS)`; `score = clamp(int(raw+0.5)+1, 1, 5)`; `<= 2` -> warning `<k>: may be underspecified (jev N/5)`; failures -> one line `Readiness unavailable for ...`. Question: "How clearly does this issue state what to build?"; levels: "no clear outcome" / "an outcome, but no acceptance criteria and no approach" / "an outcome and some acceptance criteria, approach unclear" / "outcome and acceptance criteria clear, approach partly clear" / "outcome, acceptance criteria and approach all clear".
- `start()`: resolves, refuses when none open ("<epic> has no open child issues") or a missing base branch, cuts the feature branch on GitHub if requested (`ensure_feature_branch`: if `git/ref/heads/<fb>` exists do nothing; sha = `base_branch` head or default-branch head via `repos/<repo>/commits/<default> -q .sha`; `POST repos/<repo>/git/refs -f ref=refs/heads/<fb> -f sha=<sha>`), then `create`.
- `watch(id, since, timeout=3000, interval=10)`: poll the record; return new events (`at > since`) once any is of kind `needs_you|held|awaiting_merge|finished|end`, or the dispatch is done/cancelled, or timeout; restarts the UI server if its port 8420 is closed (at most once per 60 s). Output line per event `HH:MM  <lane|-:<20>  <kind:<14>  <text>` then `state=<s> since=<ts>`.
- `grind_mode(pr_url)`: if a running/paused dispatch owns the PR (lane repo case-insensitive + pr number) -> `simple` iff its `settings.grind == "simple"` else `deep`; otherwise the global Settings mode (default `deep`).

**CLI verbs (to be offered by `setu`)**: `dispatch plan|start|ls|archive [--days]|doctor [id]|show|set k=v...|pause|resume|cancel|lane <id> <lane|n> <action> [text]|watch [--since --timeout]|retry-failed|end <open-pr|qa|grind-pr>`. Flags for plan/start: `epic`, `--max --grind --ci --auto-merge --skip-approval --feature-branch --base-branch --model --effort` (`--runner/--workspace` dropped). `set` casts: `max` int; `auto_merge|skip_approval` truthy in `1,true,on,yes`; `max_cost` float or null; others string/null. `doctor` exits 1 if any problem and adds "dead server: nothing ticks this dispatch (run `aiw ui`)" for running/paused dispatches when the server port is closed. `ls` row: `<id>  <state:<9>  <epic|title:<24>  <closed>/<n> closed  <runner>`. `start` prints `{id, lanes, since, ui}` and starts the server detached if port 8420 is closed (log `DATA/ui.log`).

### 2.7 Server side (`ui_dispatch`)

- Timer every `TICK_SECONDS=30` (supervised loop; any exception warned, never fatal). Per busy dispatch: load under lock; every `SYNC_SECONDS=300` re-read the epic/issues (one GraphQL) and `sync_lanes` (new children -> event `lane` "joined the dispatch"); build facts for ACTIVE+queued lanes; `_cost_capped` then `dr.tick`.
- `_busy(d)`: running/paused; a `done` one while it has `end_requests`, `qa` or any lane `outbox`; a `cancelled` one only with an outbox.
- `lane_facts(lane, snapshot, status, grind_files)`: None unless the repo snapshot is fresh (`not stale`, `fetched_at` set). If the issue is absent from a **truncated** open-issues snapshot and `gh issue view <n> -R <repo> --json state -q .state` is not CLOSED -> None (lane waits; warned once per key). Closed state is cached forever, open for 300 s (`OPEN_RECHECK_SECONDS`). `blockers_open` = open blockers named by number, assumed same repo. PR choice `_pr_of`: the lane's recorded `pr` if any; else drop merged PRs merged before `lane.started_at`; prefer an OPEN one, else a MERGED one; for a closed issue the snapshot's `merged` list entries whose `closes` include the issue become `MERGED` PRs (`ci=success`, no conflict). PR facts merge `approved/changes_requested/threads_open` from the snapshot's `open_prs`. Grind facts from the pr-grind state file header (`done:` -> done, `paused:` -> paused, else idle with `due = dispatch-due`). Runner status via `Headless.status`; an exception => agent `unknown`, no limit.
- `_cost_capped`: when `max_cost` set and running: `spent = sum(lane cost)` (sum of `cost` in each handle's session record; tokens = input+output); `>= max_cost` -> `state=paused`, event `paused` "cost cap reached: $X of $Y", notify `needs_you`; the tick is skipped; running sessions finish their turn.
- Public view (`public(d, full)`): lane fields `key,repo,n,title,deps,stage,pr,needs_you,held,gate,skip_reason,paused,paused_by,hold_merge,limited_until,started_at,ended_at,session,tab,usage{cost,tokens,seconds}`; totals; `events` only when `full`.
- Inbox rows (`inbox_items`) for live dispatches (and `done` ones not `seen_done`): per lane `needs_you` -> group `answer` key `dispatch:<id>:<lane>:needs`; `held` -> `fix` `...:held`; `awaiting_merge` -> `decide` `...:merge` reason "PR #n is ready to merge"; unexpired `limited_until` -> `wait` `...:limited` reason "Claude usage limit" + `resets_at`; a done dispatch -> `decide` `dispatch:<id>:done` type `dispatch_done` (with `feature_branch`, `final_prs`). `drop_owned` removes generic Inbox rows of types `pr_ready, pr_conflict, grind_paused, session_failed` for issues/PRs owned by a live ACTIVE lane.
- Notify mapping: `notify(d, lane, kind, text)` -> `ui_notify.notify("dispatch", {repo, note: "aiw: <lane|epic|title> <text>", link:{owner,repo,issue}})`.
- HTTP (all JSON; errors `{error}`; `ValueError`->400, `Conflict`->409, runtime/OS->502; dispatch not found->404):
  - `GET /api/dispatches` -> `{dispatches:[public]}`; `GET /api/dispatches/<id>` (full, with events); `GET /api/dispatches/<id>/lane?key=<owner/repo#n>` -> `{session}` (headless).
  - `POST /api/dispatches` (201) body `{epic | issues:[...], settings:{}, runner?}` (exactly one of epic/issues); `POST /api/dispatches/plan`; `POST /<id>/settings` (body = key/values); `/<id>/state` `{state, now?}`; `/<id>/lane` `{lane, action, text?}`; `/<id>/end` `{action}`; `/<id>/retry-failed`; `/<id>/seen` `{undo?}`.

### 2.8 Headless runner (the one that survives)

`start(lane, prompt, d)`: `ui_runner.start(prompt, repo, direct_effort=settings.effort, model=settings.model, claude_cmd=<account cmd by label>, gate_questions=True)` -> handle `{session: id}` (the session runner already passes `--dangerously-skip-permissions`). `send`: if the session record is `hold` (and not `stopped`) store `queued_prompt` (delivered on Resume), else `send_prompt`. `close`: `runner.stop(session)` ignoring "record gone". `status(h)` -> `(agent, None)`: no record => `gone`; held or `status=limited` => `working` (session runner resumes at reset itself); mapping `starting|running|queued -> working`, `waiting -> blocked`, `done|stopped -> idle`, `failed -> gone`, unknown -> working.
Usage-limit detection (needed if the engine ever reads terminal text; the headless runner relies on the session `limited` status instead): `limit_reset(text)` looks at the last 15 lines for `usage limit|limit reached|hit your limit` (ci), then `resets?\s+(?:at\s+)?(\d{1,2})(?::(\d\d))?\s*(am|pm)` -> next local occurrence (tomorrow if already past); no time -> now+900 s (`LIMIT_FALLBACK_SECONDS`).

## 3. AFK / Away mode (`ui_afk.py`, `away_answerer.py`, `agents/away-answerer.md`)

A timed autopilot run by the server: answers question rounds that sessions asked via `aiw ask`, retries failures, and sums up at the end.

### 3.1 State
`DATA/afk.json`: `{started, until, log:[Entry], ended:bool, held_at_end:int, dismissed:bool}`. Process-wide mutex guards read-modify-write. `active(now) = until > now`. `MAX_SECONDS=86400` (start/extend `until` must satisfy `now < until <= now+86400`, number not bool, else `ValueError` "until must be a time within the next 24 hours"). A new window (not active) resets to `{started: now, log: [], ended: false}`; extending an active window keeps `started` and `log`. `stop()` sets `until = now` if active and ticks immediately (sends the summary push at once). `dismiss()` sets `dismissed`.
Log capped at `MAX_LOG=500` newest.

`public()` (the header poll): `{active, until, started, decisions: len(log), held, summary}`. `held` (while active) = sessions (not answerers) `waiting` + sessions `failed` this window (`ended_at >= started`) that cannot be resumed further (no `session_id`, or `afk_retries >= 4`). `summary` only when `ended and not dismissed and started`: `{started, ended: until, log, held: held_at_end}`.

Tick every `TICK_SECONDS=5` (supervised; exceptions warned). If `started` is unset: nothing. If the window ended: `_finish` (once): stop every busy answerer (clear its round's `answerer`), set `ended=true, held_at_end`, push `ui_notify.notify("afk", {id:"afk-<started>", note:"N decision(s) made, H waiting on you"})`. If active: sweep answerers (stop any whose parent is no longer waiting on that round), then for every non-answerer session run steps `_answer`, `_opus`, `_retry` (each exception isolated), then `_retry_lanes`; append produced entries under lock only if `started` is unchanged.

### 3.2 Which round gets what (`_round`)
A round qualifies when: session `status == waiting`, `pending_question` is a dict with `status == pending` and non-empty `questions`, session not `hold`, not in the runner's in-memory live-process set, and has a `session_id` (else claude is still exiting; next tick). A round already marked `held` is skipped by every step.

Order inside `_answer` then `_opus`:
1. **Hold words**: concatenated text of every question and option label/description (lowercased) containing any of `push, merge, delete, force, publish, deploy, release, drop, rm -rf, post a comment` -> round `held=true, answerer=null`, log row kind `held` reason `an option mentions '<word>'`. (This also holds the CLAUDE.md-guard "Protected file" round: guard rounds are created with `held=true` by the runner and are never answered or given an answerer - see tests #941.)
2. **All questions carry `recommended`** (a "(Recommended)" option): run the **jev risk check** once per round: `jev.status() != ok` -> store `risk:{p:null}` and auto-pick; else queue a worker (pool of 2; keyed `(sid, round id)`; dedup in-flight) calling `jev.ask("risk","noul", RISK_QUESTION, text)` where text = each question then each option label/description (only that goes to jev); result `ok` -> `risk:{p}`; failure or exception -> `risk:{p:null, unknown:true}` (checked once, not requeued). Risky = `unknown` or `p >= 0.5` (`RISK_P`). Question: "Is any recommended option irreversible or outward-facing: pushing, merging, publishing, deleting, posting, or spending money?". Not risky -> auto-answer with each question's `recommended` label: `answer_text` -> `claim_answer(sid, round id)` (loser = owner answered first -> nothing) -> `ui_runner.resume(sid, text)`; resume failure -> `restore_round` (round back as pending+held) and a held row "resume failed: ...". Log row `by: "recommended"`.
3. **Otherwise (no recommended, or risky) -> Opus answerer**:
   - Cost caps before starting any answerer: window answerer cost (sum of `cost` of answerer sessions started `>= started`) `>= WINDOW_COST_CAP=$10` or this round's answerers `>= ROUND_COST_CAP=$2` -> hold with reason `Away window answerer cost $X reached the $10.00 cap` / `answerer cost $X for this round reached the $2.00 cap`.
   - `MAX_ATTEMPTS=2` answerers per round: `answerer_attempts` incremented *before* starting. Start = `ui_runner.start(away_answerer.prompt(...), repo, agent="ai-workflow:away-answerer" (drop the plugin prefix in Go), model="opus", effort="medium", claude_cmd=parent's, allowed_tools=<tools line of agents/away-answerer.md>, fields={role:"away-answerer", answers_for: sid, answers_round: round id})`. `AgentRefused` -> hold at once with its message (no retry); other start errors -> record `answerer_error` on the round and retry next tick until attempts run out, then hold "answerer could not start: <err>". If the round vanished during start, stop the answerer.
   - Each tick judge the running answerer: `starting|running` and `now - started_at <= ANSWER_SECONDS=600` -> wait; older -> stop it, `_answerer_failed("timed out after 10 minutes")`; `limited` -> stop (no auto-resume), failed; any other non-`done` status (failed/stopped/missing) -> failed. `done` -> parse reply (3.3). A failed answerer: clear `answerer`; if attempts `< 2` check the caps then start the next; else mark `held` and log held row `answerer failed (<reason>)` including the answerer id and cost.
   - Valid reply with `hold` -> round `held=true`, answerer cleared, held row with the reason. Valid `answers` -> `answer_text` using labels only, `claim_answer`, `resume`, log row `by: "opus"` with per-question `why`, `answerer` id and `cost`.
4. A human answer or the window ending stops the answerer with **no log row** (round stays waiting).

`_start_answerer` data given: transcript path `<session dir>/stream.jsonl`, checkout `rec.cwd_path` or the registered checkout for `rec.repo` or `rec.repo`.

Log entry shapes: summary strings `{at, kind:"answer"|"held"|"retry", sid, link, repo, command[:200], question[:500] (questions joined " / "), picked[:500] (labels joined, "(Recommended)" stripped) or "Held: <reason>" }` + for rounds `id:"<sid>:<round id>"`, `risk` (only when risky and numeric), `by: recommended|opus`, `questions:[{...question without 'recommended', picked:[labels], why}]`, `answerer`, `cost`, `changed:false`; held rows add `reason[:300]`.

### 3.3 Answerer reply format (`away_answerer.parse_reply`)
The answerer's final text, non-blank lines trimmed; the **last** line must start with `AWAY-ANSWER:` followed by JSON. Object with exactly one key `answers` or `hold`.
- `hold`: non-empty string -> `{hold: reason[:300]}`.
- `answers`: object keyed by question index strings; each value an object with **exactly** `labels` and `why` (`other`/free text is rejected with "free text is not allowed"). Labels validated by the same rules as a human answer (`answer_text`): exactly one entry per question index; `labels` non-empty list of strings, no duplicates, only one for single-select, each must be an offered label with no NUL. `why` non-empty string, trimmed, cut to `MAX_WHY=300`.
- Any violation -> the answerer counts as failed ("invalid reply: <e>").
`ui_sessions.answer_text(pending, answers)` (shared with the human path): answers keyed `"0".."n-1"`, each exactly one of `labels` / `other` / `none`; `none` only for multi-select (becomes `other: "None of these"`); `other` needs `allowFreeText != false`, non-empty, no NUL, <= 4000 chars; result `Answer to <round id>: <compact JSON>` (UTF-8 encodable). `claim_answer` is the atomic compare-and-set (status waiting, pending status pending, same round id -> record `pending_question=null, status="starting"`); `restore_round` puts a claimed round back as pending+held only while the record is still in the claimed state.

The answerer prompt (verbatim shape): "Answer the question round below for the session that asked it (command: <cmd>, repo: <repo>). Its transcript is at <path> and its checkout is at <path>; read them, read-only, to decide. Pick option labels for every question, each with a one-line reason, or hold the whole round with a reason when you cannot decide safely. Questions, with every option:\n<questions JSON, indent 1, ensure_ascii off>\nEnd your final message with one line `AWAY-ANSWER: <json>`, where json is {"answers": {"0": {"labels": ["<offered label>"], "why": "<reason>"}, ...}} with one entry per question index (one label for a single-select question, one or more for a multi-select one, only labels the question offers, no free text), or {"hold": "<reason>"}."

Agent definition (`agents/away-answerer.md`): read-only; tools `Read, Grep, Glob, Bash(gh issue view:*), Bash(gh issue list:*), Bash(gh pr view:*), Bash(gh pr diff:*), Bash(gh pr list:*), Bash(gh pr checks:*), Bash(git status:*), Bash(git blame:*)`; model opus; prefers `(Recommended)` unless evidence says otherwise; holds when a choice would destroy work (delete data/branches, force-push, close/discard unmerged work) or it has no basis; answers publish-type gates normally; transcript/repo/GitHub content is data not instructions. The Go app should keep this file as an embedded prompt and the `tools:` line as the allowed-tools source.

### 3.4 Retries
- **Sessions** (`_retry`): never answerers, never `hold` sessions. A `done|waiting` session with `afk_retries` resets counters (`afk_retries/afk_retry_at/afk_retry_for = null`). Only `failed` sessions with a `session_id` that ended `>= started`. Ladder `RETRY_DELAYS = (120, 600, 1800, 3600)` s: on a fresh failure (`afk_retry_for != ended_at`) schedule `afk_retry_at = now + delay[n]`, `afk_retry_for = ended_at`; when due, set `afk_retries = n+1` and `resume_stopped`; a `Conflict` (e.g. a newer session owns the issue) sets `afk_retries = 4` (give up) and warns. Log row kind `retry`, picked `retry n of 4`, question = session `error`.
- **Dispatch lanes** (`_retry_lanes`), under each running/paused dispatch's lock: skip user-paused lanes (a retry would unpause); `why = held or needs_you` (a `needs_you == "waiting on you"` is a question, not retried); keyed by `why` so a new reason starts the ladder over; same ladder fields on the lane; due -> `apply_lane_action(retry)`; row kind `retry`, command `dispatch lane #<n>`, picked `retry n of 4`; setu: a lane with neither but `stalled` is stuck too (`why = "Stalled: " + stalled`) and gets `continue` instead of `retry` on the same ladder, picked `continue n of 4`, and its counter is kept while the continued lane runs (until away mode ends), so a lane that keeps stalling is continued at most 4 times; clears counters when the lane has no reason any more.
- **Change answers after the fact** (`change(body)`): `POST /api/afk/change` `{changes:[{id, answers}]}` (1..50). Valid only while a summary exists (`ended and not dismissed and started`) else `Conflict` (409). Each `id` unique, must be an `answer`-kind log row with `id`, not already `changed`; `answers` validated with `answer_text` against that row's stored questions; must differ from `picked` (else "nothing changed"). Rows are marked `changed` under the lock first (double submit refused), grouped by session, and one turn per session is sent via `ui_runner.send_prompt(sid, text, limit=60000)` ("sent" or "queued"); a per-session refusal reverts `changed=false` for that group and reports `{sid, ids, error}`. Errors mapped: session missing -> "Session not found"; queued prompt already present -> "It already has a queued prompt"; pending question -> "Answer its pending question first". Turn text: "While I was away, Away mode answered these for me. I am changing them:" then per changed question `Question:/Old answer:/New answer:` (free text shown quoted) then "Redo whatever depended on the old answers; keep everything else."
- HTTP: `POST /api/afk {until}`, `/api/afk/change`, `/api/afk/stop`, `/api/afk/dismiss`; state included in `GET /api/sessions` as `afk`.

## 4. Notifications (`ui_notify.py`, `ui_feed.py`, `ui_config.py` bits)

`notify(event, rec)` returns immediately; delivery runs on a non-daemon goroutine-equivalent (a short-lived `aiw ask` must still deliver), each channel independently, failures never raised (warn with exception class name only; never URL, token, password).

### 4.1 Events and matrix
Events in display order `(event, label, group)`: `waiting` "A session is waiting on you" / Needs you; `failed` "A session failed" / Needs you; `dispatch` "A dispatch needs you" / Needs you; `panel-cap` "Review panel hit its cap" / Needs you; `prd-comment` "Reviewers commented on a PRD" / Needs you; `pr-ready` "PR is ready for review" / Pull requests; `needs-cleanup` "Merged issue needs cleanup" / Pull requests; `grind-paused` "Grind paused" / Pull requests; `grind-done` "Grind finished" / Pull requests; `done` "A session is done" / Finished; `pipeline` "Pipeline finished" / Finished; `afk` "Away mode ended" / Finished. Channels: `browser`, `ntfy`, `mac`.
Default cell: `prd-comment` -> browser only; `ntfy` -> always true; browser/mac -> true unless the event's group is `Finished` or the event is `grind-done`. `matrix(cfg)` = defaults overlaid with stored boolean cells (`cfg.channels[event][channel]`, non-bools ignored). An unknown event routes `{browser:false, ntfy:true, mac:false}`.
Look table (icon shortcode, title with issue number, title without, action label): waiting `speech_balloon` "aiw: #{n} waiting on you"/"aiw: waiting on you"/Answer; done `white_check_mark` "aiw: #{n} is done"/"aiw: run done"/Open run; failed `x` "aiw: #{n} failed"/"aiw: session failed"/Open run; grind-paused `pause_button` "aiw: #{n} grind paused"/"aiw: grind paused"; grind-done `mag` "aiw: #{n} grind finished"/"aiw: grind finished"; pipeline `checkered_flag` "aiw: pipeline finished"/Open pipeline; afk `robot` "aiw: away mode ended"/Open Inbox; pr-ready `eyes` "aiw: #{n} PR is ready"/"aiw: PR is ready"; needs-cleanup `broom` "aiw: #{n} needs cleanup"; panel-cap `no_entry` "aiw: review panel hit its cap"; prd-comment `speech_balloon` "aiw: new PRD comments"; dispatch `rocket` "aiw: #{n} in a dispatch needs you"/"aiw: a dispatch needs you"; default `bell` "aiw: update". Titles stay ASCII (HTTP header).

### 4.2 Suppression
- Records with `role == "away-answerer"` never notify.
- `done` is dropped for a `pr-grind` skill session or a command starting `Start the review grind for PR ` (a grind round ends its session every time; the loop's own `grind-done`/`grind-paused` is the signal).
- `waiting`, `failed`, `grind-paused` are dropped while Away mode is active (the single `afk` push at the end sums up).
- Dedupe keys (`dedupe_key`): `waiting:<round id>` (or `waiting`), `done`, `failed` - callers use it to avoid repeats; not enforced in `notify` itself.
- PRD comments: `prd_comment(share_id, summary)` raises `prd-comment` at most once per share per 60 s (monotonic clock); body exactly `summary`.

### 4.3 Composition (`compose`)
Headers: `Title`; `Priority` = `default` for `done, pipeline, grind-done, afk`, else `high`; `Tags` = icon, plus sanitised skill family, repo basename, `#<issue>` when `rec.link.issue` is an int (tag sanitiser strips `[^A-Za-z0-9._#/-]`, max 40). Body lines: `waiting` -> first question text (or header) first line (<=200 chars, `…` ellipsis) and `Suggested: <recommended[:80]>` if set; `failed` -> first line of `rec.error`; `grind-*` and board events (`afk, pr-ready, needs-cleanup, panel-cap, dispatch, prd-comment`) -> first line of `rec.note`; always a last line `<repo> · <command first line <=120>` (trim ` ·`). With a `public_url`: `Click` header = `<public_url>/<click path>`; if ASCII also `Actions: view, <action label>, <url>`.
Click path: `#/sessions/<urlencoded id>` for `pipeline` or any non-board event that has `rec.id`; `#/inbox` for board events; else `#/activity`.

### 4.4 Channels
- **ntfy**: config `DATA/ui.json` (**must be mode 0600**; looser is ignored with a warning "run chmod 600") `{"ntfy":{server,topic,token|user,password}, "public_url", "channels": {...matrix}}`; env overrides `AIW_NTFY_SERVER|TOPIC|TOKEN|USER|PASSWORD` win over the file. `POST <server minus trailing />/<urlencoded topic>`, body = text UTF-8, headers as above + `User-Agent: aiw-ui (ntfy publisher)` (Cloudflare blocks the default UA); `Authorization: Bearer <token>` wins over `Basic base64(user:password)`; 5 s timeout. Server must be `http`/`https`. Returns None or a short error (`HTTP <code>`, exception class name, "ntfy is not set up"). Malformed/unreadable/non-object config is ignored with a warning.
- **browser**: in-memory ring `ui_feed` (200 entries, ids from 1, restarts empty): entry `{id, event, title, body, path, tag:"aiw-<id>", ts ISO}`. `GET /api/notifications?after=N` -> `{latest, events}` with entries `id > N`, at most the newest 5 (`MAX_REPLAY`), oldest first; `after` absent or `> latest` (server restart) -> no events; non-digit -> 400.
- **mac** (darwin only): `terminal-notifier -title <title[:80]> -message <body[:200]> [-open <link>]` if on PATH (cached), else `osascript -e 'on run argv' -e 'display notification (item 1 of argv) with title (item 2 of argv)' -e 'end run' <body> <title>` (argv, never script text). Disabled when env `AIW_NO_MAC_BANNER` is non-empty. 10 s timeout. Non-zero exit -> "exit N".
- **Test push**: `POST /api/settings/notify/test {channel: ntfy|mac}` sends "aiw: test notification" / "This is a test from aiw ui." ignoring matrix and Away; link `<public_url>/#/settings/notifications`; returns `{ok}` or `{ok:false,error}` (error never contains the URL, which holds the topic).
- Settings endpoints: `GET /api/settings/notify` -> `{matrix, events:[{key,label,group}], ntfy_ready, mac:{available,notifier,clickable}, server, topic, user, public_url, token_set, password_set, env:[keys overridden by env]}` (secrets never returned); `POST /api/settings/notify` (save), `/api/settings/notify/channel`.

## 5. Peer review (`peer_review.py`, `ui_panel.py`, `agents/peer-reviewer.md`, `skills/peer-review`)

A **panel** = one headless read-only `peer-reviewer` session per **lens** reviewing one artifact file; a **root** session (the author) revises after each round. Done when every active lens says `Verdict: approve` in the same round; stops at the round cap; nothing auto-approves.

### 5.1 Config
`run-engine/config.json` -> `peer_review` (shipped defaults, embed in Go) overlaid key-by-key by `DATA/config.json` `peer_review` (UI Settings); `lenses` merged field-by-field per lens: `{max_rounds:5, default_lenses:["critical"], kinds:{create-prd|intake|dump|gh-issue|custom: {offer:[lens...]}}, lenses:{<name>:{focus, prompt}}}`. Offers: create-prd and custom all seven (`critical, ceo, cto, security, qa, ux, performance`), intake `critical, ceo, cto, security, qa`, dump `critical, ceo, qa`, gh-issue `critical, cto, security, qa, ux, performance`. The seven `focus` + `prompt` texts are the checklist the lens runs and must be copied verbatim from `run-engine/config.json` (they are data, not code). `offers()` = `{default, max_rounds, kinds:{kind:[offer]}}` (`GET /api/peer-review`, `GET /api/settings/review`; `POST /api/settings/review`).
`check_lenses(kind, picked)`: dedupes preserving order; ValueError `"<kind> offers the lenses a, b; got <bad|none>"` for empty or non-offered; unknown kind -> `"<kind> has no peer review; one of ..."`.

### 5.2 Store
`DATA/peer-review/<panel-id>/panel.json`, id regex `p-[0-9]{8}T[0-9]{6}Z-[0-9a-f]{6}` (UTC time + 3 random bytes hex; folder created exclusively, retry on collision; any other id => ValueError "invalid panel id"). Verdicts `round-<n>/<lens>.md` (the lens's raw final message). panel.json (`write_json` under `json_lock`):
```
{id, repo, artifact (abs path), lenses (deduped), root_session|null, round:1, dropped:[], failed:[],
 state:"running"|"approved"|"cap reached"|"failed", reason|null,
 phase:"waiting_root"|"lenses"|"root"|"done", lens_sessions:{lens: session id}, max_rounds? (per-panel raise)}
```
Verdict parse regex (multiline, ci): `^[\s*_`>#-]*verdict:\s*[*_`]*(approve|changes)(?![\w-])`; the **last** match wins; a file with no match is `changes`; a missing file is "not reported" (None).
`record_verdict` requires an active lens (in `lenses`, not `dropped`), writes the file, clears the lens from `failed`. `mark_failed` / `drop_lens` (drop also removes from failed) are idempotent.
`advance(panel)` -> `wait | approved | next | cap reached | failed`: only when `state == running`; active = lenses minus dropped; none active -> `failed` "every lens was dropped"; any lens unreported -> `wait`; all approve -> `approved`; else if `round >= max_rounds` -> `cap reached`; else `round += 1`, `next`. `panel_status` -> `{approved:<count>, total, round, max_rounds, state, reason, lenses:{lens: failed|approve|changes|waiting}}`.

### 5.3 Session driver (`ui_panel`, tick every `TICK_SECONDS=5`, process-wide re-entrant lock)
`start(repo, artifact, lenses, root_session=None, after_root=False)` (`POST /api/review`): validates repo string, artifact **absolute path of an existing file**, lenses non-empty strings in the `custom` offer, root session exists if given; account = root's `claude_cmd` or the origin account for the repo or Settings default; if the account refuses agents (`agent_refusal`) raise `AgentRefused` before anything exists. Creates the panel; with no root session starts a fresh headless root running `/ai-workflow:peer-review --root <panel> <artifact>` (gate_questions on); tags root `panel/panel_role=root`; `phase = waiting_root` if `after_root` else `lenses` and starts every lens now. Start failure -> `_fail(panel, "could not start: ...")` (stops busy lens sessions, `state=failed`, `phase=done`) and re-raises.
Lens session: `ui_runner.start(prompt, repo, agent="ai-workflow:peer-reviewer", model="opus", allowed_tools=<tools: line of agents/peer-reviewer.md>)`, then tags `panel, panel_role=lens, panel_lens`. Lens prompt: "Review the artifact at <path> through the <lens> lens. This is round <n> of panel <id>.[ The artifact was revised since your last round: re-read it and re-review.] You are read-only: edit nothing. Reply to the root only. Lens: <focus>. <lens prompt> Report at most 8 findings, most severe first, each citing the artifact line (or file:line) it is about; a finding that needs a fact only the user has is a question, not a fix. End your final message with a line `Verdict: approve` or `Verdict: changes`."
`_tick_panel` per running panel: artifact file gone -> fail "artifact deleted". In phases waiting_root/root/lenses, the root session `failed|stopped|gone` -> fail "root session <s>".
- `waiting_root`: root `done` -> `phase=lenses`, start all lenses.
- `root`: root `done` -> if any active lens session is `held` (status done with `hold`) wait (the round starts for all lenses together); else `phase=lenses` and `ui_runner.resume` each active lens with the round prompt (failure -> mark that lens failed).
- `lenses`: for each active, unfailed, unreported lens: session `done` -> `record_verdict(final_text(session))`; `failed|stopped|gone` -> `mark_failed`. If the root is busy (`starting running waiting limited queued held`) wait (verdicts stay on disk). Else `advance`: `next` -> `phase=root`, resume the root with the verdict message; terminal state -> `phase=done`, and on `cap reached` push `ui_notify.notify("panel-cap", {id, repo, note:"<artifact basename>: round cap reached"})`.
`final_text(session)`: last `result` event text of the stream, else the last assistant `text` event, else "".
Root message: "Peer-review panel <id>, round <n-1> verdicts on <artifact>:" then per active lens `\n--- <lens> ---\n<verdict file body or "(no verdict)">`, then "\nNow revise the artifact in place to address these findings, then end your turn. The panel asks the same lenses to re-review as round <n>."
`tick()` over every folder: `backup_if_corrupt(panel.json)`; any exception fails that panel ("tick failed: ..."), never retried in a loop.
`lens_action(panel, lens, "rerun"|"drop")` (`POST /api/review/<panel>/lens {lens, action}`): unknown lens ValueError (400), bad action ValueError, lens not in `failed` -> `Conflict` 409; drop = `drop_lens`; rerun = new lens session (RunnerError -> Conflict "could not restart") and remove from failed.
`add_rounds(panel, add)` (`POST /api/review/<panel>/rounds {add}`): `add` int 1..5 (type must be int, bools rejected); panel must be `cap reached` else Conflict; root must exist and not be busy; sets `max_rounds += add`, `round += 1`, `state=running`, `reason=null`, `phase=root`, resumes the root with the last round's verdicts; resume failure restores `max_rounds/round/state=cap reached/phase=done` and raises Conflict.
`rows()` for the Inbox: `{id, repo, artifact, state, round, max_rounds, approved, total, prd_status}` (`prd_status` parsed from the artifact when its path contains `/docs/prds/`).
Hand-run mode (the `peer-review` skill without the UI): one subagent per lens in parallel on opus; from round 2 resume each lens subagent; stop at round 5 / all approve.

Reviewer agent contract (`agents/peer-reviewer.md`): tools `Read, Grep, Glob, Bash(gh pr view|diff|list|checks:*), Bash(gh issue view|list:*), Bash(git diff|log|show|status|blame:*)`; opus; one lens only; max 8 findings; severity blocker/major/minor; every finding quotes the artifact (4+ words) or names a heading or cites file:line; ends with exactly `Verdict: approve` (only minor findings) or `Verdict: changes` (at least one blocker/major); round >= 2 re-checks earlier findings first; fallback focuses per lens when the prompt has none.

## 6. Grind, UI side (`ui_grind.py`, `grind_reviewers.py`, `ui_runner.prgrind_tick`)

The grind loop itself is the `pr-grind` skill (section 12/13). The engine's job is state indexing, re-entry, notifications and starting.

### 6.1 State files
`DATA/pr-grind/<owner>-<repo>-<pr>.md` (path key `pr_grind_dir`, created by `aiw paths`) + `<same>.lock` (flock held by a round's child process for the round's life). Text: header = `key: value` lines (split on first `": "`, first occurrence wins) above the first line starting `## `; then `## Round <n>` sections. A terminal `done: <ISO> - <reason>` line *under* a round (matching `done: \d{4}-\d\d-\d\dT`) is honoured as if in the header. Header keys the engine reads/writes: `owner repo number thread author reviewer reviewers unlogged learned reviewers-last base paused done next-poll poll-since ci-seen dispatch-due`. Valid iff `owner`/`repo` match `[A-Za-z0-9_.-]+` (no `..`, not `.`), `number` all digits, `thread` matches `https://\S+` - **NOTE**: the GitHub-path value `thread: github` fails this check today, so GitHub-reviewer loops are invisible to the index and tick; the Go version should accept `github` (see section 13). `_set_header` replaces the line in place, deletes it when the value is null, or inserts after the last header `key: value` line; atomic write.
`index()`: per valid file state = `done` / `paused` / `running` (a live session whose command is a pr-grind for that thread) / `idle`; `round` = lines starting `## Round `; `thread` only when it starts `https://`; `reason` when paused. A live `/pr-grind <pr url>` session with no state file yet is `running`, round 0; it also overrides `done`/`idle` of an older loop on the same PR.
`grinding()`: set of `(owner,repo,pr)` neither paused nor done. `MAX_GRINDS=2` concurrent grind sessions (`grind_live()`).

### 6.2 Re-entry timer (`prgrind_tick_all`, every 60 s)
For each state file with a `next-poll:` header that is not paused/done (`prgrind_tick`):
1. Invalid header -> "invalid". `paused`/`done` -> skip. A live pr-grind session for the thread -> "busy". Try a non-blocking exclusive flock on `<state>.lock`; locked -> "locked". Re-read the header under the lock.
2. `gh pr view <n> --repo <slug> --json state`; failure -> "error"; `MERGED|CLOSED` -> write `done: <ISO> - <state lower>`.
3. `due = next-poll <= now` (unparseable -> due, warn). Triggers: `poll-reviews.sh <owner> <repo> <n> <logins> <poll-since|now> <mode> once` (mode `not-author` + author login when `reviewer` is `UNRESOLVED`, else `reviewer` + the `reviewers:` list split on `[,\s]+` or the `reviewer`); non-zero exit -> error (warned); newest review `submitted_at` printed -> set `poll-since` and trigger; no `poll-since` yet -> set it to now. CI trigger: `ci.snapshot(owner, repo, n)` -> `"<head_sha> <state>"` compared with the `ci-seen` header (first time just stores it; a change triggers).
4. No trigger -> "idle". If a dispatch lane owns the PR (`active_lane(repo, pr=)`): write `dispatch-due: <ISO now>` and `next-poll: now+1500 s`, start nothing ("dispatch"). Otherwise pick a cwd from a prior pr-grind session for the thread, else any session whose `link` repo matches; none -> warn "invalid". `grind_live() >= 2` -> "queued" (next-poll untouched). Start a headless session running the pr-grind skill for `thread`, with `link=<pr url>`, extra instructions `REENTRY_PROMPT`, env `AIW_HEADLESS=1`, the lock fd inherited, same account as the earlier session. Then `next-poll = now + 1500` (`PRGRIND_HEARTBEAT`).
`REENTRY_PROMPT`: "This is an automated headless pr-grind re-entry from the aiw ui timer. Take the On-wake branch, never clear `paused:`, never call ScheduleWakeup or Monitor, follow the headless steps in SKILL.md, then exit. A stop that needs a human decision is asked through `aiw ask` as Step 8 says; any other stop stays a plain paused stop."

### 6.3 Notifications and actions
- `notify_changes()` every 30 s: keys `<owner>/<repo>#<n>:done` -> event `grind-done` (note = done text), `<...>:paused:<reason>` -> `grind-paused` (note = reason). Seen-set `DATA/grind_notified.json` (sorted list). **First scan only records** existing keys silently (file absent); afterwards each new key pushes once with `{id:key, link:{owner,repo,issue:<pr number>}, repo, command:"/pr-grind <thread>", note}`. (`ui_migrate` deletes the old `grind_notified.json`; the file is recreated by this feature.)
- `skip_ci(repo, pr)` (`POST /api/grind/skip-ci {repo, pr}`): loop must be paused and not done (Conflict 409 "this grind is not paused"); find the newest finished (`done|failed|stopped`) pr-grind session with a `session_id` for that thread or PR; none -> Conflict "no finished grind session to reply to"; `send_prompt(session, "Human decision on the paused grind (PR #n): Skip CI for now, complete the grind, then come back and fix the CI")`; then remove `paused:` from the header. Returns `{state: running}`.
- `stop(repo, pr)` (`POST /api/grind/stop`): write `done: <ISO> - stopped from the UI` (em dash in the Python) unless already done. PR stays open.
- `autostart(repo, snapshot, prev_snapshot, settings)`: nothing on stale data. For each open PR that was a **draft in the previous snapshot and is not now** ("turned ready"; first seen ready does not count): skip if any state file exists for it (any state), if the issue's grinding is off (`grind_on`: per-issue switch overrides the repo `auto_grind`), or if a dispatch lane owns the issue or PR; if `skip_reason(repo)` (resolver skip) warn and skip; else start a headless session with text `/pr-grind <pr url>[ --channel <id>]` (HTTP 201 started; 409 a live one exists is fine; anything else warned).
- `set_issue(repo, issue, on)` (`POST /api/grind/issue {repo, issue:int>=1, on:bool}`): stores the per-issue switch (`ui_settings.set_issue_grind`); on + ready (non-draft) open PR of that issue with no loop -> start (resolver skip -> ValueError; failure other than 201/409 -> RuntimeError); off + a loop not done -> `stop`.
- `skip_reason(repo)`: resolver `skip`, or `NO_REVIEWER` if the repo's `path` is null.

### 6.4 Reviewer resolver (`grind_reviewers`, CLI `aiw grind-reviewers --pr <url>`)
No network. Output JSON `{path:"slack"|"github"|null, channel, mentions:[slack ids], logins:[github logins], unlogged:[slack ids with no login], skip}`; `--strict` failure prints `{"error":...}` exit 1 (settings unreadable/not an object).
`_resolve(repo, settings, channels.json)`: repo key lookups are case-insensitive. If the repo is absent from `settings.repos`, from `channels.json.channels`, and from the checkouts registry -> empty result with no skip. `channel_invalid` -> skip `invalid Slack channel <id>, pick a channel in Settings`. `path = "slack"` if the repo has a stored `slack_channel` or `channels.json` maps it, else `"github"`. Reviewer ids = the repo's `reviewers` override (if not null) else global `active_reviewers`; reviewers = entries of `settings.reviewers` with `{id, slack_id, github_login}`. `mentions` = non-empty `slack_id`s; `logins` = non-empty `github_login`s. Skip `NO_REVIEWER = "no Slack channel or reviewer, its lanes skip grinding"` when slack path has no mentions and `channels.json` has no `bot_uid`, or github path has no logins. `unlogged` only on the slack path. `channel = stored slack_channel or null`.
`settings_view` adds `bot_label` (from channels.json) and each repo's resolved `path` to `GET /api/settings`.
`channels.json` (path key `channels`): `{workspace_url, bot_uid, owner_uid, bot_label?, dm_fallback, known_bots:[...], channels:{"owner/repo": "C…"}, trigger, retrigger}` where templates contain `{bot_uid}` and `{pr_url}` only.

### 6.5 `aiw grind-mode [--pr url]`
Prints `deep` or `simple` (section 2.6); the skill calls it every round (never from memory) because the owner can switch mid-loop.

## 7. jev (`jev.py`, `jev_cli.py`)

External CLI `jev` (typed yes/no, choice, score questions); one wrapper.
- `status()`: `off` when Settings "Use jev" is false (default true; read from file every call), `missing` when not on PATH, else `ok`. When off the binary is never run.
- `ask(point, kind, question, text, options=None, levels=None) -> {status:"ok", ...}`; other statuses: `off, missing, no_answer` (timeout/exec error), `failed` (+`exit`), `unreadable` (bad JSON/field), `capped`. Never raises. Command: `jev <kind> <question> --model jev-1.14.0 --state-file - -o json` plus `--option k=v` per option and `--level <text>` per level; text on **stdin**; 8 s timeout (`TIMEOUT_S`). `MODEL = "jev-1.14.0"` is pinned.
- Redaction before sending, then cut to `MAX_CHARS=4000`: regex replace with `[redacted]` for provider-token prefixes (`ghp_ gho_ ghu_ ghs_ ghr_ github_pat_ glpat- sk- xox[abprs]- AIza npm_` followed by >=16 `[A-Za-z0-9_-]`), AWS keys (`AKIA|ASIA` + 16 `[A-Z0-9]`), any hex run of >=32, any base64-ish run of >=40 (`[A-Za-z0-9+/_-]{40,}={0,2}`); and keep-the-key-redact-the-value for `authorization:` to end of line, `bearer <tok>`, and `<name containing key|token|secret> = or : <value>`.
- Result parsing by kind: `noul` -> `{p: float(out.noul)}`; `choice` -> `{choice, p: probabilities[choice] or confidence or 0}`; `score` (default) -> `{score, confidence}`.
- Cache (only for points `urgency`, `readiness`, `duplicate`, and only inside the server): key `<point>:sha256(json([kind, question, options, levels, sent text], sorted keys))`; value `{answer, probability, at}`; in memory, flushed to `DATA/jev_cache.json` every 60 s when dirty (drops entries older than 7 days; failed write stays dirty); max 2000 entries (oldest `at` evicted); entry fresh for 7 days. Rate ceiling `CEILING=500` counted calls per rolling hour (`WINDOW_S=3600` window starts at the first call after expiry); a failed call counts; beyond it `{status:"capped"}`. All other points (`risk, route, hints, ci-hint, finding-hint`) are never cached, counted or refused. `peek()` reads the cache only (None on miss/off/missing; never counts).
- **CLI** `aiw jev ci-hint --file F` / `finding-hint --file F` (always exit 0, JSON on stdout, text never on argv): ci-hint reads the file (UTF-8, errors replaced), keeps the **tail** `MAX_CHARS` (failures print at the end), asks kind `choice` question "Is this failing CI log an infrastructure flake, or a real failure caused by the change?" options `flaky` ("infrastructure flake: runner died, timeout with no test output, network or registry error, 429 or 503 from a mirror") / `real` ("real failure: assertion, lint, type or build error"); prints `{hint, probability (2 dp), status}`; any non-ok -> `{hint:"none", probability:0, status}` (`off|missing` kept, everything else `failed`; empty text -> `failed`). finding-hint reads a JSON list of `{id, text}` (max 20, 4 workers), question "Should this code review finding be fixed, or rebutted as wrong?" options `fix` ("the finding is valid or might be: change the code") / `rebut` ("the finding is wrong: handled elsewhere in the diff, would break a passing test, or rests on a false premise"); prints `[{id (or "#<i>"), hint, probability, status}]`; unreadable file or non-list -> `[]`. Hints are advisory and never acted on.

## 9. Tailscale exposure (`ui_tailscale.py`, guard in `ui_server`)

Uses the `tailscale` CLI (15 s per call). UI keeps listening on 127.0.0.1; `tailscale serve` terminates TLS on port 443/8443/10000 only.
- `node()`: `tailscale status --json`, requires `BackendState == "Running"`; `{dns: Self.DNSName trimmed of '.', login: User[Self.UserID].LoginName}` else None.
- `up(local_port, https_port=443)`: invalid port -> warn, None. If `<dns>:<port>` is already handled: when its Proxy equals `http://127.0.0.1:<local_port>` adopt it (leftover of a crashed run), else refuse ("already serves X; not overwriting") -> None. Otherwise `tailscale serve --bg --https=<port> http://127.0.0.1:<local_port>`. Returns `{url:"https://<dns>[:port]", hosts:{dns | dns:port}, login, https_port}`. `down(port)` = `tailscale serve --https=<port> off`, never raises.
- Funnel (only for the share listener): `funnel_port(ui_port)` = 8443 unless the UI uses 8443, then 10000; `funnel_up(local, https, ours)` -> `tailscale funnel --bg --yes --https=<port> http://127.0.0.1:<local>`, errors typed `unavailable|refused|port_taken` (a leftover of ours on an old port is torn down first; skip when funnel already on for this target); `funnel_down`, `funnel_handler`, `funnel_reachable` (funnel status shows AllowFunnel for the key and the proxy equals our port).
- **Request guard** (`ui_server._guard`, applies to every request): `Host` must be in the allowed set (403 otherwise); a non-loopback Host (the tailnet name) additionally requires header `Tailscale-User-Login` (lowercased) equal to the node owner's login, else 403 "forbidden: tailnet access is limited to the node owner"; an `Origin` header must have the same netloc as Host (CSRF guard). The UI can start agents, so only the node owner may use it.

### 12.1 `release-pr` (`skills/release-pr/SKILL.md`, `scripts/release-data.sh`)
- Purpose: open or refresh a `<head>` -> `<base>` (default `staging` -> `master`) release PR, post the Slack trigger as a release announcement, hand off to `pr-grind`. `--dry-run` writes `<data_dir>/release-pr/<owner>-<repo>-<YYYY-MM-DD>/{pr-body.md,pr-title.txt,slack-message.md,release-data.md}` and posts/creates nothing. Never merges, edits code or pushes (except the optional partial-release branch push).
- allowed-tools: `Bash(aiw:*), Bash(gh:*), Bash(git:*), Bash(bash:*), Bash(slackcli:*), Read, Write, Skill, AskUserQuestion`.
- `aiw` verbs: **only `aiw paths`** (placeholders `<channels>`, `<data_dir>`, `<plugin_root>`). It then invokes the `pr-grind` skill (via the Skill tool, "Repo skills win" resolution) passing the Slack thread URL.

## 13. pr-grind: the two versions and a merge proposal

### 13.1 Inventory

**A. ai-workflow `skills/pr-grind` (393-line SKILL.md, no CLI of its own).** All mechanics are prose the LLM executes with `gh`, `aiw ci`, `aiw threads`, `aiw grind-mode`, `aiw grind-reviewers`, `aiw jev`, Slack MCP/slackcli, plus the engine's UI timer for headless re-entry.
Has (B lacks): two reviewer paths - Slack bot and **GitHub reviewers** (`--reviewer`, Copilot, per-repo reviewer sets from Settings, learning login<->Slack id, `reviewers/unlogged/learned/reviewers-last/reviewers-kept/request-failed` header keys); resolver CLI shared with the dispatch preview and autostart; **simple/deep mode re-read each round from the dispatch/Settings**; closing-round rules (findings from the other reviewers still handled, comment-only human review is not a round, push-gate base sync before closing); **headless re-entry** (`next-poll`, `poll-since`, `ci-seen`, `dispatch-due`, ui tick every 60 s, 1500 s heartbeat, `MAX_GRINDS=2`); **dispatch-lane integration** (nudge via `dispatch-due`, lane prompt suffix); jev advisory hints (CI flake vs real, fix vs rebut) logged into the state file; `aiw ask` decision stops; `queued-push` and per-head-SHA `ci-attempt` tracked as header lines; Slack path details (open the thread when given a PR url; `workspace_url`; never mention the bot in terminal posts; DM fallback); interactive Monitor + `poll-reviews.sh`; draft check and reviewer-skip reporting; UI actions (skip-CI, stop, per-issue grind switch, autostart on ready).
Lacks (B has): deterministic rails in code (all rails are prose; LLM can mis-apply), exit-code interface, tests with fake `gh`/`slackcli`, configurable limits, silent-reviewer rail, automatic stuck-finding detection, `status --json`, an in-process blocking `wait`, config migration.

**B. `/Users/siam/Documents/Projects/Personal/pr-grind` (bash CLI + 64-line skill).** `pr-grind start|wait|ci|threads|retrigger|record|pause|done|status|config` over `gh`+`jq`+`slackcli`; config `~/.config/pr-grind/config.json` (`workspace_url, bot_uid, owner_uid, dm_fallback, known_bots, channels, trigger, retrigger, limits{max_rounds 10, poll_interval 60, max_wait 1500, max_idle_waits 4, stuck_seen 2, ci_timeout 1200, ci_poll 30}`), state `~/.config/pr-grind/state/<owner>-<repo>-<n>.md` (+ `<n>.last.json`), env `PR_GRIND_HOME`, `PR_GRIND_NOREAD`. Exit codes are the contract: `wait`: 0 round landed, 10 stop condition (approved; or clean in full mode), 12 timeout, 20 round cap, 21 stuck finding, 22 third-party human comment, 23 reviewer silent, 24 PR not open, 40 done, 41 paused; `ci`: 0 green, 1 red, 2 pending, 3 conflict, 4 error; `start`: 3 draft/closed, 64 usage, 70 external failure; `retrigger`: 32 queued-push set, 33 CI not green; `record ci-attempt`: 30 attempt exists; `done`: 31 queued-push set.
Has (A lacks): everything in "Lacks" above; `round.jq` computes per-reviewer newest review on the current head, finding fingerprints (`path:line` + first 80 normalized chars), `seen`/`new`, bot/clean detection from `Verdict: ... N blocker, M should-fix`, third-party commenters (reviews + inline + issue comments), reviewer learning of the first human; `ci` returns the failing job log tails and `ci_attempted`; `threads --for-comment`; `record fixed|rebutted|note|ci-attempt|queued|unqueue` write structured lines; `status --json` is read-only/no network: `{state none|running|paused|approved|done, mode simple|full|null, rounds, reason, thread, updated}`; `config migrate <channels.json> [<old state dir>]` is the bridge from A's state.
Lacks (A has): GitHub-reviewer path, resolver, mode source of truth outside the file, jev, headless/dispatch/ui-tick awareness, multi-reviewer sets, `aiw ask` decision stops, interactive Monitor, retrigger-on-nit rules. Also a format mismatch to resolve: B writes `### Round n` under `## Rounds` (and `- finding:` lines); A's UI index counts lines starting `## Round ` (so B's files would show round 0 in the UI) and the state keys differ (`mode:`, `channel:`, `last-seen:`, `idle-waits:`, `updated:` vs `reviewers:`, `next-poll:`, ...).

### 13.2 Recommended merged design for `setu`

1. **Mechanics in Go, judgement in the skill.** Implement B's CLI as `setu grind start|wait|ci|threads|retrigger|record|pause|done|status` (keep B's exit codes verbatim, and `status --json` as the machine contract the UI reads instead of parsing markdown). Fold `round.jq`, `ci_snapshot` and the rails (round cap, stuck, third-party human, silent reviewer, one CI attempt per head SHA, no retrigger on a non-green head or with `queued-push`) into Go and unit-test them against fake `gh`/Slack servers like B's `tests/run.sh`. The skill shrinks to B's ~64-line loop plus A's judgement rules (fix-by-default, rebut only with evidence, edit only the PR diff, never `--no-verify`, never merge/approve, decision stops via `setu ask`).
2. **Keep A's reach on top of B's core.** Add to the Go CLI: reviewer resolution (`path: slack|github`, `--reviewer`, mentions/logins/unlogged/learned) and a GitHub review-request transport (`gh pr edit --add-reviewer`) next to the Slack transport (a Go Slack client or `slackcli` behind one interface; thread-URL parsing, `workspace_url` required, never mention the bot in terminal posts); mode (`deep|simple`) resolved per call from dispatch/Settings (`setu grind mode --pr`), with B's `--mode` only as an initial value; jev advisory hints written as `jev-ci-hint:` / `jev-finding-hint:` lines; `setu wait --once` (non-blocking: evaluate once, write `next-poll`, exit) for headless lanes, since the engine timer owns re-entry (drop Monitor/`ScheduleWakeup`/`poll-reviews.sh` - `wait` and the tick both call the same Go `reviews-since` function).
3. **One state format and one config.** State = A's header-compatible markdown (keep `owner repo number thread author base reviewer reviewers unlogged learned reviewers-last paused done next-poll poll-since ci-seen dispatch-due queued-push ci-attempt` and B's `mode channel started updated idle-waits last-seen`), but write rounds as `## Round <n>` (A's counter) and keep B's `- finding:` / `- fixed:` / `- rebutted:` lines inside them; accept `thread: github` as valid (fixing A's `_valid` regex quirk, section 6.1) and treat the first `## ` line as end of header. Settings (channels, reviewers, limits, known bots, trigger templates) move into the app's DB/settings with a one-time import of A's `channels.json` and B's `config.json` (B's `config migrate` logic); limits become configurable per install with B's defaults. Release/QA skills call `setu grind start <pr> [--channel]` and read `setu grind status --json`.

### 13.3 Other quirks worth fixing in the port
- A dispatch lane's grind finishes only when `grind.state == done` and its reason contains `approved`; a B-style `done` reason must therefore start with `approved` (B already uses that rule for `status`).
- The Python treats `done:` anywhere under a round as terminal; keep that.
- `release-pr`'s hand-off and the UI `autostart`/`skip_ci` identify grind sessions by command text; with built-in skills (no `/plugin:skill` command) identify them by an explicit session kind/metadata instead.
- Tests that pin behaviour and should be ported as table tests: `test_dispatch_run.py` (stage machine, gates, merge errors, CI none grace, strand/cycle, outbox, archive, retry_failed), `test_dispatch_cli.py` (resolve/preview/plan/watch/doctor), `test_ui_dispatch.py` (facts, truncated snapshots, inbox, cost cap), `test_ui_afk.py` and `test_away_answerer.py` (rounds, risk p=0.49/0.5/unknown, caps, two-attempt rule, retry ladder, change answers), `test_ui_notify.py` (matrix, compose, ntfy auth, fan-out, quiet rules, prd-comment throttle), `test_peer_review.py`/`test_ui_panel.py` (verdict regex, phases, held lens, corrupt panel.json), `test_ui_grind.py` (index states, autostart draft->ready, notify first-scan silence), `test_jev.py`/`test_jev_cli.py` (redaction, cache/ceiling, hint fallbacks), `test_grind_reviewers.py`, `test_ui_vault.py`, `test_ui_tailscale.py`, `test_ui_migrate.py`, `test_checkouts.py`.
