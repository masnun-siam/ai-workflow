## What this is

A Claude Code plugin that takes a GitHub issue to a reviewed, ready-to-merge pull request.
`/ai-workflow:run-issue` writes tests, implements, verifies, opens the PR, reviews it and
applies the fixes. It stops for a human only at plan approval, an escalated review finding,
and the final ready-to-merge handback. Supporting commands and skills around it handle intake
and issue filing, PR review and the review-fix loop, batch dispatch, and worklogs.

## Mental model

- **Orchestrator:** `commands/run-issue.md`. Runs in the user's session and does what the
  engine prints. It never decides the next step itself.
- **Stations:** the `run-*` agents in `agents/`. Each runs with fresh context and returns an
  **envelope**, a fixed-shape result. The other files in `agents/` serve standalone commands
  and are not stations.
- **Engine:** `run-engine/engine.py` reads the envelope, applies the policy in
  `run-engine/config.json` (a repo can override it with `.run-issue.json`), and names the
  next station. `engine.py` is pure and deterministic; `route.py` and the other modules in
  `run-engine/` do the I/O.
- **Ledger:** one `run.json` per run, kept in the plugin data directory and never in this
  repo. It is the only source of truth for a run (see REFERENCE, "Where state lives").
- **Evidence over trust:** no station is taken at its word. Post-checks verify each result
  before the run advances.

Vocabulary (Run, Ledger, Station, Bounce, …) is defined in `CONTEXT.md`. Use those terms.

## Code structure and stack

- **Engine and CLI:** Python 3.10+, stdlib only, with no `pip install` step. `bin/aiw` is a
  shim onto `run-engine/route.py`, which exposes every mechanical step as an `aiw`
  subcommand.
- **`aiw ui`:** a local web UI. The server is stdlib `http.server` (`run-engine/ui_*.py`).
  The frontend is vanilla ES modules plus vendored Preact and htm in
  `run-engine/ui_static/`, with no build step.
- **Agents, commands, skills:** Markdown prompts, with small sh/py helper scripts inside
  `skills/`.
- **Tests:** plain `assert` scripts at `run-engine/test_*.py`, with no test framework, no
  network and no Docker.
- **CI:** GitHub Pages publishes `docs/overview.html`.
